# 일정 알리미 — web

Next.js App Router 프론트엔드. DRF API를 바라본다.

## 설치

```bash
npm i @tanstack/react-query zustand react-hot-toast vaul
echo 'NEXT_PUBLIC_API_HOST=http://localhost:8000' > .env.local
```

운영 이미지는 `output: "standalone"` 결과물만 담는다 — 소스도 devDependencies 도
들어가지 않고 `node server.js` 하나로 돈다. `public` 과 `.next/static` 은 standalone 에
안 들어오므로(원래 CDN 이 맡는 자리다) Dockerfile 이 따로 복사한다.

저장소 루트의 `docker compose up --build` 로 API·postgres 와 함께 띄울 수도 있다.
컨테이너에서도 저장하면 바로 반영되지만, 거기서는 Turbopack 대신 **webpack + 폴링**으로
돈다 — mac 의 바인드 마운트에서는 파일 변경 이벤트가 컨테이너 안까지 오지 않아
Turbopack 이 다시 컴파일하지 않기 때문이다. 그래서 **프런트만 만지는 동안에는
호스트의 `npm run dev` 가 더 빠르다.**

`tsconfig.json`에 경로 별칭이 필요하다.

```json
{ "compilerOptions": { "paths": { "@/*": ["./*"] } } }
```

## 알아둘 것

**날짜 파싱을 직접 한다.** `new Date("2026-09-11")`은 UTC 자정으로 해석돼
한국에서 하루 밀린다. `lib/date.ts`의 `toDate`가 이걸 막는다. 가장 흔하게
터지는 버그라 날짜 문자열은 반드시 이 함수를 거친다.

**재발급은 한 번만 나간다.** 여러 쿼리가 동시에 401을 받아도 `api.ts`의
`refreshing` 프로미스를 공유한다. StrictMode 이중 실행에도 안전하다.

**주간 스트립은 목록과 같은 창을 본다.** 둘 다 오늘부터 `UPCOMING_DAYS`(7)일이다.
달력 주(월~일)로 그리면 오늘이 금요일일 때 월·화·수·목 네 칸이 목록 밖으로 나가서,
**점은 찍혔는데 아래에는 없는 날**이 생긴다. 스트립을 미리보기로 읽을 수 없게 되는
지점이라 요일 고정을 버리고 오늘부터 굴린다. 서버의 `notices/filters.py: UPCOMING_DAYS`와
`lib/date.ts: UPCOMING_DAYS`는 같은 값이어야 한다.

**창은 앞뒤로 움직이고, 목록이 따라간다.** `›`를 누르면 스트립이 다음 7일로
넘어가면서 아래 목록도 그 기간(`?from=&to=`)으로 바뀐다. 창 폭만큼 통째로 옮기므로
`9월 4일 – 10일` 다음이 `9월 11일 – 17일`이다 — 겹치지도 벌어지지도 않는다.
좌우 스와이프도 같은 폭으로 움직인다. `‹`로 뒤로 가면 지난 일정도 이렇게 본다.

**기간은 머리글이 아니라 목록의 섹션 레이블이 쓴다.** 머리글은 주간·월간 모두
`2026년 9월`로 같고, 지금 보고 있는 기간(`9월 4일 – 10일`)은 목록 맨 위에 붙는다.
둘 다 적으면 같은 말이 두 번 나온다. `rangeLabel`은 달을 넘어가면 뒤쪽에도 달을
붙인다(`8월 28일 – 9월 3일`).

**접었을 때는 날짜를 고르지 않는다.** 창이 목록과 같으니 고를 것이 없다. 탭은 그 날짜
줄로 스크롤만 하고, 일정이 없는 날은 아예 `disabled`다 — 눌러도 아무 일도 안 일어나는
칸을 만들지 않으려는 것이다. 선택과 하루 목록(`?date=`)은 펼쳤을 때만 있다.

**목록은 창 밖을 보여주지 않는다.** 머리글이 "9월 6일 – 12일"이라고 말하는데 그
아래에 9월 24일 일정이 섞여 있으면 레이블이 거짓말이 된다. 창 밖은 `‹ ›` 로 넘겨서
본다 — 그래서 `?from=&to=` 로 창 범위만 받는다.

**목록의 축은 날짜이지 공간이 아니다.** 하루를 사는 사람은 공간별로 살지 않는다.
아침에 알고 싶은 것은 "오늘 뭐 있지"지 "어린이집에 뭐 있지"가 아니다.
그래서 기본이 전체이고, 존은 색 막대와 칩 필터로만 구분한다.

**공간 이름과 색은 설정에서 바꾼다.** 공간 행을 누르면 시트에 이름 입력과 팔레트
견본이 함께 뜨고, 아래에 고른 색이 목록 카드에서 어떻게 보이는지 미리보기가 붙는다.
색을 바꾸면 칩·카드 막대·달력 점이 모두 따라가야 하므로 `notices`와 `calendar`
쿼리까지 무효화한다.

**색은 견본에서만 고른다.** 자유 색상 선택이 아닌 이유는 팔레트가 색약에서도 서로
구분되도록 맞춰져 있어서다 — 임의 색이 하나 끼면 그 보장이 깨진다. 서버도 거부한다.
다만 색은 이제 **보조 축**이다. 구분의 기본은 머리글자 딱지다.

**글씨 색은 배경에 따라 고른다.** 팔레트가 밝은 색까지 쓰는 이유는 **명도 차이가
색약에서 가장 믿을 수 있는 구분 축**이기 때문이다. 전부 어둡게 맞추면 그 축을 잃는다.
대신 밝은 색 위에는 흰 글씨가 안 읽히므로 `lib/color.ts`의 `onColor`가 대비가 큰
쪽(흰색 또는 잉크)을 고른다. 색을 배경으로 쓰는 자리는 모두 이걸 거친다.

**공간은 머리글자 딱지로 나타낸다.** "우리집"은 `우`, "회사"는 `회` — `lib/zone.ts`의
`zoneMarks`가 정하고 `ZoneMark`가 그린다. 첫 글자가 겹치면(우리집·우리회사) **갈라지는
글자를 덧붙여** `우집`·`우회`가 된다. 앞에서 더 자르는 것(`우리`·`우리회`)보다 짧고,
딱지는 이름을 적는 자리가 아니라 한눈에 갈라 보는 자리라 길이가 곧 값이다. 겹치지 않는
공간은 한 글자 그대로다 — 하나 겹쳤다고 전부 길어지면 다 같이 읽기 어려워진다.

공간 목록 전체를 봐야 정해지므로 `useZoneMark` 한곳에서 만든다 — 카드마다 따로
계산하면 같은 공간이 화면에서 다른 글자로 보일 수 있다.

**색으로만 구분하던 것을 바꾼 이유는 색약이다.** 팔레트는 색약 시뮬레이션까지 통과했지만
(최소 ΔE00 13.2), 그건 색을 **충분히 큰 면적**으로 볼 때 이야기다. 3px 막대나 4px 점처럼
작은 면적의 색은 정상 시야에서도 판별이 어렵고 색약에서는 사실상 안 읽힌다. 그래서 색이
아닌 축을 하나 더 얹었다. 색은 딱지의 배경으로 남아 있다 — 지우면 색이 보이는 사람이 쓰던
단서를 뺏는 셈이고, 두 축이 같은 것을 가리키면 읽는 사람이 편한 쪽을 고른다.

**존 이름을 카드에 통째로 쓰지는 않는다.** 제목 앞에 붙이면 제목보다 먼저 읽히고
같은 이름이 연달아 나오면 시끄럽다. 한 글자면 훑는 속도를 늦추지 않는다.
`우`가 무슨 공간인지는 존 칩이 그대로 범례가 되어 알려준다 — 칩에는 딱지와 이름이
나란히 있다.

**주간 스트립은 빈 날을 보여준다.** 목록은 항목이 있는 날만 나오므로
"이번 주 금요일이 비었는지"는 목록으로 알 수 없다. 스트립은 높이 90px로
그 정보를 준다.

**달력은 세 가지 방법으로 연다.** 달 이름 탭, 손잡이 탭, 아래로 스와이프.
손잡이 하나만 두면 처음 여는 사람이 못 찾는다. 좌우 스와이프는 보고 있는 기간을
넘긴다 — 접혀 있으면 주, 펼쳐져 있으면 달.

터치 이벤트가 아니라 **포인터 이벤트**를 쓴다. 마우스·트랙패드에서도 같은 제스처가
동작하고, 손을 떼는 것은 `window`에서 받는다. 위로 크게 끌면 손가락이 달력 밖으로
나가는데 래퍼에서만 `pointerup`을 받으면 그 제스처가 통째로 사라지기 때문이다.
`setPointerCapture`는 쓰지 않는다 — 캡처 중에는 `click` 대상이 래퍼로 바뀌어
날짜 탭이 죽는다.

**펼치면 읽는 방식이 바뀐다.** 월간 그리드는 화면 절반을 쓰고 점만 보이므로,
펼친 상태에서는 아래 목록이 선택한 하루만 보여준다(`/notices?date=`).
접으면 다시 여러 날이 이어지는 목록으로 돌아간다. 같은 화면이지만 용도가 다르다.

**날짜를 누르면 등록으로 이어진다.** 그 날짜가 채워진 채 시트가 열린다.
등록 시트를 레이아웃에 두고 `store/ui.ts`로 여는 이유가 이것이다. 비어 있을 때만이
아니라 **일정이 있어도 버튼을 둔다** — 같은 날에 하나 더 얹는 일이 흔한데,
탭바의 `+`로 열면 날짜가 비어 있어 다시 골라야 한다.

**단 지난 날은 아니다.** 지난 날짜로 등록하면 알림 시각이 이미 지나 있어서 서버가
저장 직후 예약된 알림을 전부 한꺼번에 쏴버린다. 그래서 지난 날의 빈 칸에는 등록
버튼 대신 안내 문구만 두고, 폼의 `<input type="date">`에도 `min`을 건다. 서버도
같은 이유로 400을 낸다 — 어느 한쪽만 막으면 뚫린다.

**달력 점은 목록과 별도 API다.** `/calendar?from=&to=`가 날짜 → 색 배열만
돌려준다. 주를 넘길 때마다 일정 본문을 다시 받을 필요가 없다.

**완료는 지우는 것이 아니다.** 오늘 일정이라도 이미 끝난 것이 있다. 지우면 기록이
사라지므로 `completed_at`으로 덮는다. 완료하면 목록과 달력 점에서 빠지고 남은
알림도 나가지 않는데, **예약 자체는 남아 있어 취소하면 되살아난다.**

**빠지는 것은 오늘 이후뿐이다.** 지난 일정은 기록이라 완료해도 목록에 남고 흐리게
(취소선 + `완료`) 그려진다. 끝낸 것을 지워버리면 지난 기간을 넘겨봤을 때 그 날이
비어 보인다. 하루 보기(달력을 펼쳤을 때)도 같은 이유로 완료한 것을 보여준다 —
여기가 완료를 되돌리는 경로다. 상세의 알림 목록도 완료 상태에서는 "대기 중"이
아니라 "보내지 않음"으로 적는다 — 오지 않을 알림을 올 것처럼 쓰지 않는다.

**발송 상태 점은 발송(초록) → 아직(회색) 순이다.** 실패는 초록으로 세지 않아
카드에서는 회색에 섞이고, 무엇이 실패했는지는 상세가 "발송 실패"로 알려준다.
**아직 보내는 쪽이 없어서** 지금은 전부 회색이다. 서버가 `Alert.status` 를
채우기 시작하면 그대로 색이 붙는다.

**아이콘은 `Logo.tsx`의 `variant` 하나로 바꾼다.** 기본값 `calendar`의
점 2개 + 빈 점 1개는 목록 카드의 발송 점과 같은 표기다. PWA 아이콘
(`public/icon-192.png`, `icon-512.png`)도 같은 모양으로 내보내면 된다.

**수정 시 발송된 알림은 유지한다.** 프론트는 알림 코드 배열을 통째로 보내므로,
서버가 `sent_at`이 있는 Alert는 남기고 나머지만 교체해야 한다.

## 서버가 맞춰줘야 하는 것

- `APPEND_SLASH = False` (경로 끝에 슬래시 없음)
- refresh 토큰은 httpOnly 쿠키, 응답 본문에는 `access_token`만
- `Zone.color` · `Zone.name` — `PATCH /zones/{id}` 로 변경 (색은 팔레트 밖 값 거부)
- 팔레트는 색약 시뮬레이션으로 최소 ΔE00 12 이상을 지킨다 (`zones/cvd.py`)
- `GET /zones/palette` — 고를 수 있는 색 목록
- `Zone.upcoming_count`는 `later`를 포함한 전체 개수
- `GET /notices?filter=upcoming|later|past&zone={id}` — zone 생략 시 전체
  - `upcoming` — 오늘부터 7일 (`UPCOMING_DAYS`, 시작일 포함)
  - `later` — 그 이후 전부
  - 정렬은 `event_date, zone_id, id` — 같은 날 안에서 공간끼리 모인다
- `GET /notices?from=&to=&zone={id}` — 기간. 주간 목록이 쓴다
- `AlertItem.status` — `""` 예약 · `"sent"` 발송됨 · `"fail"` 발송 실패
  - 실패에는 `sent_at` 이 비어 있다 (없으면 상세가 실패를 "대기 중"으로 그린다)
- `Notice.completed_at` — 목록과 달력 점 양쪽에서 빠져야 한다 (보내는 쪽도 이 값을 봐야 한다)
  - 단 **지난 일정은 남긴다** (기록이라 지우면 그 날이 비어 보인다)
  - 단 `?date=` 하루 보기에서는 돌려준다 (되돌릴 유일한 경로)
  - `PATCH /notices/{id}` `{"completed": true}` 하나로 토글 (`alerts` 없이)
- `GET /notices?date=2026-08-19&zone={id}` — 하루치
- 셋이 겹치면 `date` > `from`/`to` > `filter` 순으로 이긴다
- `GET /calendar?from=&to=&zone={id}` — `{"2026-08-19": [{"zone": 3, "color": "#2F7A63"}]}`
  - 색만으로는 색약에서 못 읽는다. 달력 칸도 머리글자를 그리므로 `zone` id 가 필요하다
- 지난 날짜 `event_date`로는 등록 거부 (기존 지난 일정 수정은 허용)
- `Zone.ntfy_topic` — 사용자가 직접 정한다. 비워 보내면 서버가 만들어 준다
  - `^[A-Za-z0-9_-]{4,64}$`, **전체에서 유일** (겹치면 남의 알림이 온다)
